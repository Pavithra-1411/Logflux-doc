[LOGFLUX]

Universal Log Pre-Processing Framework

A zero-trust, self-healing log pre-processing pipeline that ingests logs from any network device, preserves raw bytes as tamper-evident evidence, uses AI-assisted discovery to auto-generate parsers for unknown formats, validates them in a WASM sandbox before a human approval gate, and normalizes everything into a common event schema.

// THE PROBLEM

Log management is broken at scale

01

Format Fragmentation

Every vendor ships a proprietary log format. Firewalls, routers, and endpoints each require hand-written parsers that silently break when firmware updates.

02

No Evidence Integrity

Raw log bytes are transformed before storage, destroying the cryptographic chain-of-custody required for legal admissibility and forensic investigation.

03

Silent Parser Drift

When a device firmware changes its log format, existing parsers silently emit malformed or empty fields - no alerts, no fallback, just corrupted telemetry in your SIEM.

04

AI Without Guardrails

LLM-generated parsers shipped directly to production without deterministic validation or human review introduce a new class of supply-chain vulnerability.

// HOW IT WORKS

The Pipeline, Stage by Stage

Every log byte passes through a deterministic, auditable chain. No stage can be skipped, no AI output can reach production without passing through the human approval gate.

// WHY IT'S DIFFERENT

Four design principles that separate LOGFLUX

01

AI Proposes. Humans Decide.

The LLM and Drain3 engine produce parser proposals and nothing more. Before any AI-generated code touches production logs, it must pass deterministic WASM sandbox validation and explicit human analyst approval. There is no automated fast-path. The human gate is a hard architectural constraint, not a configuration option.

Generic: LLM output → production
LOGFLUX: LLM → WASM sandbox → human review → signed bundle → production
02

Zero Raw-Data Loss by Construction

The raw byte fork to the Evidence Vault happens before any parsing or transformation. Even if a parser crashes, the original bytes are intact, cryptographically hashed, and Merkle-witnessed. You can always re-parse from ground truth.

Generic: parse → store (raw discarded)
LOGFLUX: raw vault write (atomic) → parse → store
03

Self-Healing Drift Detection

Most log pipelines silently degrade when device firmware changes log format. LOGFLUX monitors per-parser field extraction rates via Prometheus. When rates drop below threshold, the system automatically re-routes the affected stream into discovery and alerts analysts.

Generic: drift → silent garbage in SIEM
LOGFLUX: drift → alert → auto re-discovery → review
04

Air-Gap Native Design

LOGFLUX is designed for classified and air-gapped environments. The LLM runs locally via llama.cpp/Ollama — no external API calls. Signed plugin bundles are single-file, self-contained, and transferable by USB without a registry or network.

Generic: cloud LLM API + plugin registry
LOGFLUX: local LLM + signed single-file bundles, zero external deps

// FEASIBILITY & IMPACT

Ready to deploy. Designed for the right audience.

Technical Feasibility

  • All core components are open-source and battle-tested (Python, Wasmtime, Drain3, SQLite)
  • WASM sandboxing provides language-agnostic, hardware-independent parser isolation
  • Local LLM (Qwen3 0.6B) runs on commodity hardware — no GPU required for the prototype
  • Ed25519 signing is lightweight, fast, and widely supported across deployment environments
  • Docker Compose deployment reproduces the full stack from a single command

Deployment Feasibility

  • Single-node prototype deploys in minutes via scripts/setup.sh or Docker Compose
  • Air-gap native — no external network required after initial setup
  • Signed plugin bundles distribute via USB/physical media without a central registry
  • Prometheus-compatible metrics integrate with existing monitoring infrastructure
  • Production scale-out uses the same core pipeline with drop-in backend replacements

Compliance Feasibility

  • SHA-256 + Merkle + Ed25519 chain-of-custody supports NIST SP 800-92 requirements
  • Raw byte preservation satisfies evidence integrity for legal admissibility
  • RFC 5848 alignment for cryptographic signing of syslog messages
  • Human approval gate creates an auditable record for every parser decision
  • Zero raw-data loss policy aligns with forensic and regulatory retention requirements

// GET STARTED

Up and running in minutes

bash
# 1. Clone the repository
git clone https://github.com/Sachin-MS-77/LOGGER.git
cd LOGGER

# 2. Run the setup script (creates venv, installs deps, pulls Qwen3 0.6B)
chmod +x scripts/setup.sh
./scripts/setup.sh

# 3. Start the pipeline
source .venv/bin/activate
python -m logflux run

# 4. (Optional) Run the test suite
python -m pytest tests/ -v

# 5. (Optional) Run benchmarks
python scripts/benchmark.py
powershell
